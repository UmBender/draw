# ADR-T07-1 Screen-space tessellation in the renderer

## Context

The renderer must draw every shape through the [[T03 Camera|camera]] with
widths clamped to at least 1 px ([[ADR-0013 World-space widths and zoom limits]]),
cull off-screen shapes ([[ADR-0006 Redraw on demand]]) and not allocate per
frame. macroquad offers two ways to do this:

- set a `Camera2D` and draw in world coordinates, letting the GPU transform;
- transform points on the CPU with our own `Camera` and draw in pixels.

macroquad's `draw_circle`, `draw_ellipse` and `draw_ellipse_lines` also
allocate two `Vec`s per call and always use 20 sides, which is both an
allocation per joint and visibly polygonal for large ellipses.

## Decision

- `shell::render` draws in **screen space** with macroquad's default camera:
  every world point goes through `core::camera::Camera::world_to_screen`,
  every width through `render::screen_width`.
- Discs (round joints and caps), ellipse fills and ellipse outlines are
  tessellated by `shell::render` itself with `draw_triangle` /
  `draw_line`, which do not allocate. The number of segments follows the
  on-screen radius (`render::circle_segments`, chord error ≤ ¼ px, clamped
  to `8..=256`), generated by incremental rotation (no trig per vertex).
- Rect outlines are four opaque bands centred on the edges, so corners are
  square and the outline straddles the geometry like `Shape::bounds` assumes.

## Alternatives considered

- **`Camera2D` + world-space drawing** — the 1 px minimum width and the
  constant-width selection outline would need per-shape conversion anyway,
  and macroquad's `draw_line` thickness would be in world units, so thin
  lines vanish when zoomed out.
- **macroquad `draw_circle` / `draw_ellipse_lines`** — allocate per call
  and use a fixed 20 sides.

## Consequences

- One code path for widths and culling, all testable with the pure helpers
  (`screen_width`, `is_visible`, `cull_rect`, `circle_segments`,
  `selection_rect`).
- The CPU transforms every vertex each frame; fine for contest-sized
  drawings, revisit in [[T14 Performance and release validation]] if not.

## Rollback plan

Only `src/shell/render.rs` changes: swap the private tessellation helpers
for macroquad's primitives or set a `Camera2D`; the public API stays.
