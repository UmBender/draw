# 2.0 baseline

Measured on 2026-11-12 at version 1.6.0 (`main` at `e59e429`). Each table is
printed by a script in `scripts/audit/` (run it with `bash scripts/audit/<name>.sh`),
so the baseline can be repeated and compared by later tasks. Nothing here is
estimated; a gap says so.

## 1. Frame times

Script: `scripts/audit/frames.sh` (`DRAW_FRAME_TIMES=1`).

**Not measured on the i5-8250U.** This audit ran unattended on the
owner's development machine with an empty document and no way to build the
ADR-T24-5 scene (5k strokes, zoom ladder) by hand. The only numbers
captured are for an empty page (0 shapes), so they say nothing about the
budgets:

| Event | Empty page, this machine |
|-------|--------------------------|
| first full re-render | 26.4 ms (startup) |
| steady full re-render | 0.07–0.17 ms |
| overlay re-render | 0.11 ms |
| append re-render | 0.37 ms |

The numbers of [[ADR-T24-5 Redraw budgets]] (overlay 0.12–0.17 ms; full
re-render 15–20 ms zoomed out, 40–60 ms at medium zoom) predate
[[T26 Pan and zoom without re-rendering]] and are **still unverified**.
**Owner:** build the scene (see the perf-scene recipe: Ctrl+A, Ctrl+D
doubling to 5k strokes), run `scripts/audit/frames.sh` on the i5-8250U at
three zooms and fill this table:

| Zoom | Overlay (ms) | Full re-render (ms) | Append (ms) |
|------|--------------|---------------------|-------------|
| zoomed out | | | |
| medium | | | |
| zoomed in | | | |

## 3. Coupling

Script: `scripts/audit/coupling.sh`.

- `core` imports nothing from `shell` (0 files): the headless boundary of
  [[ADR-0003 Headless core and thin shell]] holds.
- 15 files of `shell` import `core`.
- Most imported inside `core`: `geom` (31 files), `palette` (22), `shape`
  (20), `document` (16), `command` (14), `snapshot`, `input`, `editor`
  (13 each), `camera` (11). Leaves nobody imports: `svg`, `snapshot_image`,
  `laser`.
- **19 files mention macroquad**: `src/lib.rs`, `src/main.rs`, `src/theme.rs`,
  `src/core/mod.rs` and 15 in `src/shell`. The ones in `core/mod.rs`,
  `lib.rs` and `theme.rs` are the leak the workspace split of
  [[T132 Workspace split with unsafe levels]] must close (colours and key
  codes use macroquad types).

## 6. `dyn`, `Box<dyn` and `unsafe`

Script: `scripts/audit/unsafe-dyn.sh` (lines, comments skipped).

| Pattern | `src` | `vendor/miniquad` |
|---------|-------|-------------------|
| `dyn ` | 11 | 29 |
| `Box<dyn` | 5 | 25 |
| `unsafe` | 0 | 544 |

The 11 in `src` are 10 `dyn`-using lines and one string:

- `core/smoothing.rs:344`: a `&dyn Fn` closure parameter (replaceable by a
  generic).
- `core/svg.rs:48,146,162`: `&dyn Outlines` (the glyph-outline source;
  replaceable by a generic parameter).
- `shell/crash.rs:104,110,390-397`: `dyn Any + Send` for the panic payload
  (the standard library's type; unavoidable at that call, so allow-list).
- `shell/export.rs:57`: `dyn Error` in `Error::source` (the standard
  library's signature; allow-list).

`src` has no `unsafe`; all of it lives in the vendored miniquad.

## 7. macroquad and miniquad calls draw really uses

Script: `scripts/audit/mq-calls.sh`.

- **Drawing**: `draw_line` (18 call sites), `draw_rectangle` (17),
  `draw_triangle` (4), `draw_mesh` (4, one `Mesh`/`Vertex` user),
  `draw_circle` (2), `draw_texture_ex` (4), `draw_text_ex` (2),
  `clear_background` (5), `set_camera` / `set_default_camera` (2 each),
  one render target.
- **Window and loop**: `next_frame` (3), `screen_width` (14),
  `screen_height` (2), `screen_dpi_scale`, `Window::from_config`, `Conf`
  with `UpdateTrigger`.
- **Types**: `Color` (7 imports), `KeyCode` (5+2), `MouseButton`, `Rect`,
  `vec2`, `Image`, `Texture2D`, `FilterMode`, `DrawTextureParams`, `Camera2D`.
- **miniquad reached through macroquad** (our patches): `EventHandler`,
  `KeyMods`, `signal::{FatalSignal, QuitSignal}`, `diag::{Device, BackendEvent,
  BackendRecord}`, `conf::{LinuxBackend, Platform}`, `seat::{DeviceChange,
  device_change, has_release_request}`, `pen::pointer_shadowed_by_pen`,
  `window::dpi_scale`.

That is one window, triangles and lines with one mesh type, textures, a
render target, keyboard, pointer, pen and seat events: the surface the own
backend must cover, far smaller than macroquad's.
