# 2.0 architecture proposal

Written after the owner's answers of 2026-11-12. Nothing here is decided: the
spec step of [[T50 Version 2.0.0 refactor]] turns each section into ADRs and
child tasks. Numbers marked *measured* come from the ADRs; the rest are
estimates and say so.

## 1. What the owner decided (2026-11-12)

1. **X11 stays.** This reverses goal 1 of T50 (remove X11/Xwayland) and the
   deprecation of [[T46 Native Wayland by default and Xwayland deprecated]].
   The `x11` Flatpak socket, the X11 pen pressure path and `DRAW_BACKEND`
   stay; a new ADR reverts the deprecation.
2. **The patched miniquad goes; a backend of our own replaces it.** miniquad
   (26.7k lines vendored, 19 of our files use macroquad) is the base of
   macroquad, so **macroquad goes too**: the window, input, clipboard,
   GL context and the renderer become ours.
3. **The release depends on the end-to-end suite**, on X11 and on Wayland.
4. **`unsafe` is allowed**, in confined modules, with a full test set per
   primitive (§5).
5. **Threads are welcome only with a measured gain** (§7).
6. **All the quality proposals are accepted** (§8).
7. **No dynamic dispatch, as far as possible**, and compile-time techniques
   (tagless final, GADT-like encodings, type states) to catch bugs early
   (§4).
8. **The control engine is an automaton** (§3).

"2.0.0 adds no features" still holds: the user sees the same app, only
faster and with fewer bugs.

## 2. Shape of the code

A cargo workspace, so the rule "no `unsafe` here" is enforced by the compiler
per crate and not by habit:

| Crate | Holds | `unsafe` |
|-------|-------|----------|
| `draw-types` | Newtypes and units: `World`, `Screen`, `Px` coordinates, typed ids, `NonEmpty`, validated values | `forbid` |
| `draw-core` | Document, history, tools, snapshot, TeX, recognition and the **automaton** (§3). Pure: input events in, effects out | `forbid` |
| `draw-gfx` | Retained renderer over an abstract GPU (§6) | `deny`, allowed only inside `gpu/gl.rs` |
| `draw-sys` | The platform: X11, Wayland, EGL/GLX, xkb, clipboard, tablet | allowed, each primitive documented and tested (§5) |
| `draw` | `main`, wiring, command line | `forbid` |

The two backends are chosen **once at start**, and the whole program is built
for each (`fn run<P: Platform>()`, called from a `match` in `main`), so there
is no `dyn Platform` anywhere: two monomorphisations, one binary.

## 3. The control engine as an automaton

Today the editor is one struct whose behaviour depends on a handful of
`Option` fields (`palette`, `sheet`, `text_edit`, `active_gesture`, a laser
held-key) checked in different orders in `handle`, `apply`, the shell and the
tests. Each combination that nobody thought of became a bug or a fuzz
failure (the laser with an open palette, undo with an open sheet, a `?` that
closed the sheet during fuzz).

**Proposal: a hierarchical state machine (statechart) with a pure
transition function, a Mealy machine whose outputs are data.**

```text
step : (Machine, Input) -> (Machine, Vec<Effect>)      -- total, pure, no I/O
```

- **Input** is one closed enum: pointer, key, text, scroll, paste, resize,
  `Tick(Instant)`, and `Reply(..)` for the answer to an effect (a clipboard
  read, a finished export). Time is an input, so the laser, autosave and the
  settle timers are deterministic and testable.
- **State** is a product of independent regions, each a sum type:
  - `Interaction`: `Idle | Gesture(Gesture) | TextEdit(Edit) | Palette(..) | Sheet(..)`.
    A modal overlay is a *state that captures input*, not a flag that every
    handler must remember to test.
  - `Gesture` is itself a sum with one sub-automaton per tool
    (`Pen: Down → Drawing → Commit`; `Select: Idle → Marquee | Moving | Resizing(Handle)`;
    `Text: Placing → Editing`).
  - Orthogonal regions: `Tool`, `Page` (typed, `0..PAGE_COUNT`), `Camera`, `Selection`, `Laser`, `Minimap`.
- **Effect** is data: `Redraw(Reason)`, `Clipboard(..)`, `Save`, `ExportPng`,
  `ExportSvg`, `CopyImage`, `Notify`, `Schedule(Instant)`. This replaces
  today's polling flags (`take_export_request`, `take_svg_export_request`,
  `take_copy_image_request`, `take_save_request`, joined in the shell by
  `serve_requests`) with one queue.
- **Totality by construction.** Transitions are `match`es over
  `(State, Input)` with no wildcard arm (`clippy::wildcard_enum_match_arm`
  denied in the crate). Adding an input or a state does not compile until
  every cell is decided, *including "ignored"*, which is written down.
- **Invariants as types**, not as checks: `Selection` holds ids that exist
  (typed ids from an arena with generations), `PageIx` cannot be 6,
  `Zoom` cannot be NaN, a `Stroke` is `NonEmpty<Point>`.
- **The diagram is generated from the table** and a test fails if the docs
  and the table differ, so the statechart is never a drawing that lies.
- **Checked by model, not only by example.** A reference model (a few
  dozen lines) and `proptest` over event sequences compare the machine
  against it; reachable-state exploration up to depth *n* checks that
  every state can reach `Idle` with `Escape` (no state traps the user).

This is the same behaviour as today expressed in a form the compiler and
the tests can walk. It also dissolves `editor.rs` (10.5k lines) by itself:
each region becomes a module that owns its states.

## 4. No dynamic dispatch, and bugs found by the compiler

- **Tagless final for the edges.** The effects of the app are written as
  traits that interpreters implement:

  ```rust
  trait Platform { type Window; fn poll(&mut self) -> Option<Input>; fn clipboard(&mut self) -> ...; }
  trait Gpu      { type Buffer; fn upload(&mut self, ..) -> Self::Buffer; fn draw(&mut self, ..); }
  fn run<P: Platform, G: Gpu>(p: P, g: G, machine: Machine) { .. }   // monomorphised, no dyn
  ```

  Interpreters: the real X11, the real Wayland, a **recording** one (keeps
  every call, for golden tests and the shell fuzz without a window) and a
  **null** one. The same `run` is tested with the recorder and shipped with
  the real backends.
- **GADT-like encodings, within what Rust has.** Rust has no GADTs, so:
  - *typed requests*: `trait Request { type Reply; }`, so a function that
    sends a `GetSelection` can only receive a `Selection`;
  - *type states* for protocols that have an order (a Wayland surface is
    `Created → Configured → Mapped`; calling `attach` before `configure` does
    not compile);
  - *indexed ids* (`Id<Shape>`, `Id<Page>`) so a page id cannot be used as a
    shape id;
  - *units*: `Point<World>` and `Point<Screen>` are different types, which
    removes the whole class of "forgot to convert" bugs.
  Where a real GADT would be needed and the encoding costs more than it
  saves, the ADR says so and uses an `enum` with an exhaustive `match`.
- **Guards.** A test like the colour guard of `theme.rs` fails when `dyn `
  or `Box<dyn` appears in the source outside an allow-list that is itself
  an ADR; the `forbid`/`deny` levels above are checked by `scripts/check.sh`.

## 5. `unsafe`: confined, and every primitive fully tested

The C libraries that give an OpenGL context cannot be avoided on either
backend (EGL needs the `wl_display` of libwayland-client, the X11 path needs
the connection of libxcb), so `draw-sys` loads them with `dlopen` at run
time, as the vendored miniquad does today, and keeps `unsafe` to these
primitives: dynamic loading, the FFI calls, shared memory for buffers, and
passing file descriptors.

Every `unsafe` primitive is delivered with all of the following, or it is
not merged:

1. **A safe wrapper** whose type makes misuse impossible, and a `# Safety`
   section stating the invariant (`clippy::undocumented_unsafe_blocks` is
   denied).
2. **Unit tests** of the wrapper's invariants and of every error path.
3. **Integration tests against the real thing**: Xvfb for X11, a headless
   sway for Wayland, run by `scripts/e2e.sh`.
4. **A regression suite** with one test per bug found, named
   `regression_<ID>_<slug>` as the workflow already requires, never deleted.
5. **Tools beyond tests**: Miri for the pure parts, the address and thread
   sanitizers on the integration tests in the nightly job, and fuzzing of
   every decoder of bytes that came from a server (event decoders, protocol
   messages, clipboard formats).

Every bug found while building the backend gets its regression test in the
same change, as the owner asked.

## 6. Performance: what changes and why

Measured today ([[ADR-T24-5 Redraw budgets]]): overlay-only 0.12–0.17 ms;
full re-render 15–20 ms zoomed out; 40–60 ms at medium zoom (**not met** at
the time); MSAA 4× costs about 20 % CPU against 8 % without it while drawing.
These were measured before T26 and are **re-measured first** (§9, audit).

The own backend allows what macroquad's immediate mode does not:

- **Retained geometry**: shapes are tessellated once, kept in GPU buffers
  per chunk and keyed by shape and revision. The camera goes to the vertex
  shader, so pan and zoom re-tessellate nothing. The settle re-render and
  the blit of a stale layer (T26) stop being needed.
- **Analytic anti-aliasing** in the fragment shader (distance to the edge)
  instead of 4× multisampling: the same smooth lines for a fraction of the
  fill cost on an iGPU. Decided by measurement, with MSAA as the fallback.
- **Frame pacing by the compositor** (`wl_surface.frame`, X11 Present or a
  timer) instead of a polling loop; idle stays at 0 %.
- **Persistent glyph atlas** and instanced quads for text and key caps.

### OpenGL or Vulkan

**Decision proposed: OpenGL ES 3.0 over EGL (GLX where EGL is missing) for
2.0.0; Vulkan is an optional later task, taken only if a measurement asks
for it.** This is engineering judgement, not a measurement.

What Vulkan would give: validation layers that report misuse while
developing, explicit control of the swapchain and of presentation, command
recording on several threads, no need for `libEGL` and `libwayland-egl`
(`libwayland-client` and `libxcb` stay for the window), and the UHD 620
runs it through Mesa's ANV driver.

Why it does not come first:

1. **The measured bottleneck is the CPU, not the driver.** It is
   re-tessellating and re-sending triangles on every re-render. With
   retained geometry a frame is a handful of draw calls, which is where
   Vulkan saves little.
2. **Much more code and `unsafe`**: instance, device, swapchain,
   synchronisation, a memory allocator (ours, since no crate is allowed),
   pipelines, resize handling. Each piece needs the full test set of §5,
   and swapchain edge cases on Wayland and X11 (resize, scale,
   suboptimal presentation) are a known source of bugs. Mesa's OpenGL is
   mature and predictable.
3. **Reach.** GLES 3.0 runs on nearly all hardware with a recent driver;
   Vulkan needs newer GPUs and drivers (Intel before Skylake is partial or
   absent), and the owner keeps X11 users, who often have older machines.
4. **Scope.** The platform layer is already the largest item of the epic.

To keep the door open at no cost, the `Gpu` trait of §4 is written for
both: explicit typed resources (buffers, pipelines, textures, render
targets), a recorded list of commands that is submitted once per frame,
and no hidden global state. A Vulkan backend is then a second
interpreter of the same trait, chosen at start-up and monomorphised like
the others (still no `dyn`).

**When the answer changes**: the audit or a benchmark on the target shows
that driver overhead or frame pacing is the ceiling; or the owner drops
the hardware without Vulkan. The task below is conditioned on that.

## 7. Threads, only with a real gain

Candidates, each behind a benchmark: tessellation of chunks in scoped
threads (the only one expected to pay off for 5k+ shapes); PNG and SVG
encoding and the autosave (already off the main thread); TeX layout of
many blocks. The rule: a threaded path ships with a benchmark on the
target (i5-8250U, 4 cores) showing at least the gain the ADR names, or it
is removed. Concurrency primitives get the thread sanitizer and, where a
lock-free structure is written, `loom` tests.

## 8. Quality proposals, all accepted

1. **E2E in the release gate**: `scripts/release.sh` runs `check.sh --fuzz`
   and `e2e.sh` on X11 and on Wayland and refuses to package otherwise.
   The goldens move with the code in the same commit.
2. **Coverage** with `cargo llvm-cov` in CI, a ratchet that fails when
   a module's coverage falls.
3. **Break up `editor.rs` and `tex.rs`**: `editor.rs` dissolves into the
   automaton's regions (§3); `tex.rs` (11k lines) splits into parser,
   layout, metrics and glyph tables.
4. **Fuzz of the shell** through the recording platform of §4: sequences
   of raw input events against `input_map` and the machine, no window.
5. **Dependencies**: ADR-0014 ("macroquad only") already no longer describes
   the tree (`ttf-parser`, `png`). A new ADR lists the real set and says
   each addition needs an ADR; macroquad leaves the list.
6. **The `unsafe` policy** of §5 is an ADR amending ADR-0014.

## 9. Order of work

Each step ships green and the app keeps working: the new platform is built
next to macroquad and replaces it only when it passes the same e2e suite
(a strangler, not a big bang).

1. **Audit and baseline**: re-measure frame times, coverage, `dyn` count,
   module sizes; write the 2.0 ADRs (this proposal, split).
2. **Quality rails first** (§8.1, 8.2, 8.5, 8.6, the `dyn` guard): they
   protect everything after.
3. **Types and the automaton** in `draw-core`, with the old `Editor` kept
   as an adapter until the fuzz and snapshot tests agree.
4. **The `Platform` and `Gpu` traits** and the recording interpreter; port
   the shell to them while still on macroquad.
5. **`draw-sys`, Wayland first, then X11**, each primitive with its §5 set;
   tablet pressure on both.
6. **`draw-gfx`**: the retained renderer; measure against the budgets.
7. **Threads** where the benchmark shows a gain.
8. **Remove `vendor/miniquad` and macroquad**, packages, release 2.0.0.
9. **Optional, after 2.0.0 or in parallel with step 7: a Vulkan backend**
   for the `Gpu` trait, only if the condition of *OpenGL or Vulkan* holds.
   It enters the plan as a task marked `optional`, with the same §5 test
   set, and it does not block the release of 2.0.0.

## 10. Risks, stated plainly

- **Size.** The vendored miniquad is 26.7k lines; a backend limited to what
  draw uses (one window, GL, keyboard, pointer, tablet, clipboard, two
  protocols) should be well under that, but it is the largest item of the
  epic and the one most likely to find platform quirks (compositor
  differences, IME-less keyboards, tablet drivers). Wayland and X11 are
  separate bodies of work.
- **C libraries remain.** "Our own" means our own code over libwayland,
  libxcb, EGL and xkbcommon loaded with `dlopen`, not a reimplementation of
  those protocols; a pure-Rust Wayland or X11 transport cannot hand EGL a
  display handle.
- **GADTs are emulated**, not available; §4 says where.
- **The Vulkan task can be built wrongly early.** A `Gpu` trait shaped
  after OpenGL's hidden state would make it expensive; the trait is
  reviewed against Vulkan's model in the spec step, before any backend.
- **A retained renderer moves the bug risk** to cache invalidation; hence
  the equivalence tests between the cached and the recomputed geometry.
